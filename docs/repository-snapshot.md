# 仓库内生成快照

## 已确认的行为

用户要求在仓库中直接提供单独文件，已批准使用 `rime/` 目录，并授权 Actions 自动提交、推送该目录。Release ZIP 继续保留。

`rime/` 内容来自同一次验证通过的 ZIP，包含方案、OpenCC 数据、许可及版本/验证记录；额外的 `GENERATED.json` 标明自动生成，并记录快照文件摘要。

## 同步与发布顺序

1. 构建任务生成、验证并上传 ZIP，仍只持有只读仓库权限。
2. 发布任务检出本次构建的代码提交，下载对应 ZIP。
3. 校验 ZIP 路径、大小、文件摘要、方案清单及验证结果；拒绝路径穿越、符号链接、重复路径和非项目文件。
4. 同步到 `rime/`。现有目录必须带有生成标记且文件未被手工修改；否则停止，不覆盖。
5. 只提交 `rime/`；文件未变化则不创建提交。普通快进推送，不强推；遇到远端并发提交就失败，避免覆盖他人修改。
6. Release 指向包含快照的提交，上传完成后才公开。

GitHub Actions 的自动提交使用 `GITHUB_TOKEN`，不会递归触发新的 push 工作流；发布内容指纹也不包含 `rime/`，避免生成内容改变自身输入。

## 本地操作

```sh
python3 scripts/release.py sync /path/to/OpenCCGovForRime.zip rime
python3 -m unittest discover -s tests -v
```

只更新自动管理的目录。同步前校验全部内容，在同一文件系统的临时目录中写好新快照再替换旧目录。替换失败时尝试恢复；如果恢复也失败，保留 `.govrime-sync-*/old/` 供恢复，不删除旧快照。

不要手动修改或格式化 `rime/`，包括其中的 README、JSON 和 YAML。YAML 使用 PyYAML 的合法缩进风格，项目 yamllint 配置允许该风格，不改变已验证文件的字节。

- 覆盖非法包、摘要不匹配、手工修改拒绝覆盖，以及文件系统替换和恢复同时失败时保留备份。
